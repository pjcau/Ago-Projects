# Contributing Guidelines

Thank you for considering contributing to this project! Please follow these guidelines to ensure a smooth collaboration.

## How to Contribute

1. Fork the repository.
2. Create a new branch for your feature or bug fix.
3. Make your changes.
4. Write or update tests to cover your changes.
5. Run the existing test suite to ensure nothing is broken.
6. Submit a pull request.

## Pull Request Process

- Ensure your code compiles and passes all tests.
- Keep pull requests focused on a single change — avoid mixing unrelated changes.
- Provide a clear and descriptive title and description for your PR.
- Reference any related issues in the PR description.

---

### ⚠️ Important Rule

**Ogni modifica al codice deve essere accompagnata da test unitari.**

Every code change must be accompanied by unit tests. This rule applies to all contributions, whether they are new features, bug fixes, or refactorings. Pull requests that introduce code changes without corresponding unit tests will be rejected.

---

## Code Style

- Follow the existing code style and conventions used in the project.
- Use meaningful variable and function names.
- Write comments only where necessary to explain complex logic.

## Testing

- All unit tests must pass before a pull request is merged.
- New features must include appropriate unit tests.
- Bug fixes should include a test that reproduces the issue before the fix.

## Need Help?

If you have questions or need guidance, feel free to open an issue or reach out to the maintainers.
